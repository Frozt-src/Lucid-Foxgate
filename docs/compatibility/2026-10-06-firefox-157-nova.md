Verified on October 6, 2026. This is a branch candidate, not a tagged release or a claim of complete visual/performance acceptance.

Dynamically assigned native/extension variables were distinguished from undefined tokens.
- Independent read-only review of both the complete branch and the new patch: no actionable code defects found.

Privileged chrome-context Marionette provided actual browser UI DOM access even though the available DevTools connector exposed page context only. **35 targeted checks passed, zero failed:** all nine group colors, extension-free counter shadow, autocomplete radius, root shadow margin, real reduced-motion media state and zero horizontal/vertical tab transitions, vertical reparenting/filter-free rail, actual URLbar result popover, matching light/dark/solid geometry and material values, open-only backdrop bridge, solid-mode blur removal, and actual horizontal overflow. A separate 720-pixel-wide window check also showed matching URLbar surface edges.

Additional live observations: app menu opened; customization background resolved; two-tab split view and top findbar aligned; findbar checked-state selectors matched. A canvas-stream video played with advancing `currentTime`; its closed native controls shadow root was inspected, and the control bar and PiP controls computed to `backdrop-filter: none` and `will-change: auto`, preserving the existing CSS safeguard.

## Remaining acceptance gates

These are unverified behavior, not passing tests:

- **Visible remote-page blur:** URLbar translucency, matching surfaces, `blur(3px)`, and bridge activation are verified. A striped local page remained visibly sharp in automated captures, including a temporary stronger-filter diagnostic. Visible backdrop sampling is therefore **not established**; computed filter values do not prove it. Inspect the candidate interactively on real pages before asserting complete glass appearance.
- **Video/compositor performance:** the canvas stream's reported decoded-frame count was zero. Advancing playback time and filter-free controls do not prove rendered-frame continuity, YouTube hover/playback responsiveness, GPU behavior, or absence of compositor stalls. Run real decoded video and measure responsiveness/frame behavior.
- **Forced colors:** the media query stayed inactive during preference-based probes. The rules were reviewed statically; actual Windows contrast-theme rendering was not tested.
- **Sensitive/other UI:** saved-password/payment/form-autocomplete popup contents, actual tab/group dragging, audible media-tab states, live download animation, and full reload/stop loading transitions remain to be exercised. Synthetic state attributes are not substitutes for these interactions.
- **Platforms/configurations:** native Mica versus non-Mica popup appearance, Linux/macOS, extension-provided tinting, and beta/Nightly remain outside this runtime run.

The branch is suitable for sharing as a reviewed candidate with these explicit limits. Keep it untagged until visual, accessibility, and decoded-video acceptance are complete.
